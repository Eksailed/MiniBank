# Веб-клиент MiniBank: план реализации

Статус: выполнено.

Связано: спецификация [2026-10-31-веб-клиент.md](../specs/2026-10-31-веб-клиент.md).

> **Для исполнителей:** план реализуется по задачам; шаги отмечены чекбоксами (`- [ ]`).

**Цель:** Клиентское SPA MiniBank (`web/`): открытие и просмотр счетов, пополнение, перевод с идемпотентным ключом, выписка, светлая/тёмная тема.

**Архитектура:** React + TypeScript + Vite; `features/*` владеют запросами и страницами, `shared` и `api` лежат ниже и ничего не знают о features. «Мои счета» хранятся в `localStorage` за интерфейсом `AccountDirectory`. Запросы идут на `/api/*`, прокси Vite снимает префикс и пересылает на `http://localhost:5050`.

**Стек:** React 19, TypeScript, Vite, react-router (v7), @tanstack/react-query (v5), @tabler/icons-react, CSS Modules, Vitest + Testing Library + user-event + MSW, openapi-typescript.

**Спецификация:** `docs/specs/2026-10-31-веб-клиент.md`

## Глобальные ограничения

- Node 20+ (на машине разработчика v24); все команды npm выполняются в `web/`.
- Деньги: по сети JSON-числа (`long`), безопасные целые ≤ `Number.MAX_SAFE_INTEGER`; на границе `api/` превращаются в `bigint`; логика UI не использует `number` для сумм и не использует `float` при разборе ввода.
- Отображение сумм: `Intl.NumberFormat('ru-RU')`, формат вида `12 450,00 ₽`; валюты только `RUB`, `USD`, `EUR`.
- `Idempotency-Key`: `crypto.randomUUID()`, создаётся при открытии формы; тот же ключ при повторе и после сетевой ошибки; новый ключ после успеха и после изменения суммы, получателя или валюты; кнопка отправки неактивна, пока запрос выполняется.
- Ошибки: ProblemDetails → `ApiError { status, title, detail }`; тексты для пользователя по статусам 400/404/409/422/500/сеть, без технических деталей, рядом с формой, не всплывающими окнами.
- Тема: `data-theme="light|dark"` на корне, выбор в `localStorage`, по умолчанию `prefers-color-scheme`, выставляется до первой отрисовки. Светлая: фон `#F6F3FF`, карточка баланса `#534AB7`, плюс `#0F6E56`. Тёмная: фон `#14161A`, карточка баланса `#2A2670`, акцент и плюс `#3DD68C`.
- Зависимости идут вниз: `features -> shared, api`; feature не импортирует другую feature, кроме её `index.ts`.
- Строка операции показывает направление (Зачисление/Списание), сумму, дату и остаток; контрагента нет в `EntryDto`.
- Тексты интерфейса на русском, sentence case, без «пожалуйста» и «успешно».
- Коммиты без строки `Co-Authored-By` и без других упоминаний Claude (требование пользователя имеет приоритет над системным напоминанием). `git push` не выполнять.
- Каждая задача заканчивается зелёными `npm test -- --run` и `npm run build`.

## Review Focus: на что смотреть при ревью

- Ввод суммы: `1,5`, `1.50`, `12 345,67` (пробел и неразрывный пробел), `""`, `0`, `-5`, `1e3`, `1,234`, значение больше `Number.MAX_SAFE_INTEGER` → понятная ошибка поля, запрос не уходит.
- Двойной клик, повтор после сетевой ошибки и правка суммы между попытками: ровно один запрос на клик, тот же ключ при повторе, новый ключ после правки и после успеха.
- Адрес `/accounts/<не GUID>` и `/accounts/<неизвестный GUID>`, а также битый JSON в `localStorage`: «Счёт не найден» или пустой список, без падения и без лишнего запроса для не-GUID.
- Перевод самому себе и между счетами разных валют: отказ с понятным текстом (клиентская проверка для себя, 422 от API для валют); валюта пополнения и перевода берётся из счёта-источника, пользователь её не выбирает.
- Ответ без JSON-тела (502 от прокси при недоступном API, пустое тело, HTML): общее сообщение, а не `SyntaxError`; выписка: «Показать ещё» исчезает, когда страница короче `pageSize`.
