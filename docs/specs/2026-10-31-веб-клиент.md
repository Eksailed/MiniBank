# Веб-клиент MiniBank: SPA для счетов, пополнения и переводов

Статус: сделано (веб-клиент, `web/`). Дата: 2026-10-31.

Связано: план [2026-10-31-веб-клиент.md](../plans/2026-10-31-веб-клиент.md); API — [ядро](2026-10-31-ядро.md).

## Цель

Основа будущего клиентского приложения MiniBank: SPA, которое работает с уже готовым API (этапы 1–2) и заложено так, чтобы вход по JWT, список счетов и лимиты (этапы 4–5) добавлялись без переписывания страниц. Визуал вторичен по отношению к структуре, но важен: утверждены макеты (см. «Визуальное оформление»).

Вне рамок этого этапа: авторизация, эндпоинт «список счетов», лимиты, раздача сборки из .NET, e2e-тесты, Docker/CI (этап 3).

## Стек

- React + TypeScript + Vite, отдельное SPA в `web/`. Нужен Node.js 22.22+ (или 24): этого требуют react-router, vitest, jsdom.
- React Router (маршрутизация), TanStack Query (запросы и кэш).
- Стили: CSS-переменные и CSS Modules. UI-кит не используется.
- Типы DTO генерируются из `swagger.json` бэкенда (`openapi-typescript`).
- Тесты: Vitest, Testing Library, MSW (мок на уровне fetch).
- В разработке `npm run dev` в `web/`; прокси Vite отправляет `/api/*` на `http://localhost:5050` (префикс `/api` снимается). CORS в API не добавляется.

## Структура `web/`

```
web/
  src/
    app/          роутер, провайдеры (QueryClient, тема)
    api/          fetch-клиент, ProblemDetails -> ApiError, сгенерированные типы
    features/
      accounts/   открытие счёта, карточка счёта, хранилище «мои счета»
      transfers/  пополнение, перевод (формы, Idempotency-Key)
      entries/    выписка с пагинацией
    shared/       UI-плитки, кнопки, форматирование денег, хук темы
    styles/       CSS-переменные обеих тем
```

Зависимости идут только вниз: `features -> shared, api`. Feature не импортирует другую feature, кроме публичного индекса.

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/` | Список «моих счетов»; кнопки «Открыть счёт» и «Добавить по ID» |
| `/accounts/:id` | Экран счёта: баланс, плитки действий, последние операции |
| `/accounts/:id/deposit` | Форма пополнения (отдельная страница, не модалка) |
| `/accounts/:id/transfer` | Форма перевода |
| `/accounts/:id/entries` | Полная выписка, «Показать ещё» |

Формы — отдельные страницы, чтобы работали прямые ссылки и кнопка «Назад».

## «Мои счета» без входа

В API нет списка счетов и авторизации. Клиент хранит ID счетов в `localStorage` (создан здесь или добавлен по ID). Хранилище скрыто за интерфейсом `AccountDirectory { list, add, remove }`. В этапе 4 реализация заменяется запросом к API по JWT; страницы и компоненты не меняются.

При открытии `/accounts/:id` с неизвестным ID ответ 404 показывается как «Счёт не найден» с предложением убрать его из списка.

## Деньги

- API оперирует суммами в минимальных единицах (`long`). По сети суммы идут JSON-числами; клиент принимает только безопасные целые (≤ `Number.MAX_SAFE_INTEGER`), на границе `api/` значение превращается в `bigint`, вся логика UI работает с `bigint`, не с `number`. Ввод больше безопасного максимума отклоняется как ошибка поля.
- Отображение: «12 450,00 ₽» через `Intl.NumberFormat` (RUB, USD, EUR).
- Ввод пользователя разбирается строкой в минимальные единицы, без `float`; лишние знаки после запятой и нечисловой ввод — ошибка поля.

## Идемпотентность

- `Idempotency-Key` создаётся один раз при открытии формы пополнения/перевода (`crypto.randomUUID()`) и хранится в состоянии формы.
- Повторная отправка и повтор после сетевой ошибки используют тот же ключ. Ответ с `Idempotent-Replayed: true` считается успехом.
- Ключ меняется после успешной операции и при изменении суммы, получателя или валюты (иначе API вернёт 422 за «тот же ключ с другим телом»).
- Пока запрос выполняется, кнопка отправки неактивна.

## Операции в выписке

`EntryDto` содержит сумму со знаком, остаток после операции, дату и `TransferId`, но не контрагента. Поэтому строка операции показывает направление («Зачисление» / «Списание»), сумму, дату и остаток. Имя контрагента («Перевод Бобу» из макета) потребует расширения API и в этот этап не входит.

## Ошибки

`api/` превращает ProblemDetails в `ApiError { status, title, detail }`. Текст для пользователя выбирается по статусу:

- 400 — подсветка поля и подсказка, что исправить.
- 404 — «Счёт не найден».
- 409 — «Счёт занят, повторите» и кнопка «Повторить» (тот же ключ).
- 422 — бизнес-причина (недостаточно средств, другая валюта, повтор ключа с другим телом).
- 500 и сетевые ошибки — общее сообщение без технических деталей.

Ошибки показываются рядом с формой, не всплывающими окнами.

## Визуальное оформление

Утверждённое направление: совмещение вариантов C (яркий акцентный) и B (тёмный fintech) с переключателем светлой/тёмной темы; кнопки действий в духе приложения Т-Банка.

- Тема: `data-theme="light|dark"` на корневом элементе, переменные из `styles/`. Выбор хранится в `localStorage`, по умолчанию берётся `prefers-color-scheme`; тема выставляется до первой отрисовки, чтобы не было вспышки.
- Светлая: фон `#F6F3FF`, карточка баланса `#534AB7`, положительные суммы `#0F6E56`.
- Тёмная: фон `#14161A`, карточка баланса `#2A2670`, акцент и положительные суммы `#3DD68C`.
- Карточка баланса — скругление ~20px; под ней ряд плиток-действий (иконка в скруглённом квадрате ~22px, подпись снизу): «Пополнить» (главная, акцентная), «Перевести», «Выписка», «Реквизиты». Строки операций — карточки с тонкой рамкой. Крупная кнопка формы — радиус ~14px.
- Иконки — Tabler (outline). Логотип и фирменный жёлтый цвет Т-Банка не используются.
- «Реквизиты» на этом этапе копируют ID счёта в буфер обмена.

## Тестирование

- Unit/компонентные (Vitest + Testing Library): форматирование и разбор сумм, `AccountDirectory`, формы (ключ не меняется при повторе, меняется после правки полей), сопоставление ошибок, переключение темы.
- Запросы мокаются MSW на уровне fetch.
- Типы из `swagger.json` проверяются сборкой: `npm run build` включает `tsc`.
- E2E (Playwright) против настоящего API — этап 3.

## Допущения и риски

- Генерация типов требует запущенного API или сохранённого `swagger.json`; в репозиторий кладётся сгенерированный файл типов, обновляется командой `npm run gen:api`.
- `localStorage` — временная мера: счета привязаны к браузеру.
- Раздача сборки из .NET и CORS для продакшена не решаются в этом этапе.
